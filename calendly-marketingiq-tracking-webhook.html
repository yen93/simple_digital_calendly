Calendly to MarketingIQ Tracking Webhook

How Discovery Call bookings reach Simple Digital's attribution tool

In October 2026 we connected MyAdventure Group's Calendly to Simple Digital's MarketingIQ attribution tool. When someone books a Discovery Call, Calendly now sends that booking straight to MarketingIQ so the agency can attribute it to the marketing source that earned it. This page explains what was set up, how it works, how to check it, and how it sits alongside our own tracking.

What this does

  • When a prospect books a Discovery Call with Cas, Calendly immediately notifies MarketingIQ (app.marketingiq.com.au).
  • MarketingIQ is Simple Digital's own reporting tool. They run our Google and Microsoft ads and use it to attribute bookings back to the campaign that drove them.
  • The link is one-way (Calendly → MarketingIQ). It doesn't change our booking form or touch our CRM.
  • It runs alongside — not instead of — our own Calendly tracking (see How it fits with our own tracking).

How it's built

The link is a webhook — a message Calendly fires the instant a booking is created — delivered to a MarketingIQ address.

Figure 1 — A booking travels from Calendly to MarketingIQ in real time; the agency's tool keeps only Discovery Calls.

The pipeline

  • Booking — a prospect books a Discovery Call on James Castrission's Calendly (calendly.com/myadventuregroup).
  • Event — Calendly fires an invitee.created event the moment the booking is made.
  • Delivery — that event is sent to MarketingIQ's endpoint, signed with a shared secret key so MarketingIQ can confirm it genuinely came from Calendly.
  • Filter — the webhook uses user scope, so Calendly sends every event type; MarketingIQ keeps only Discovery Call bookings and discards the rest.

Tech stack

  • Calendly Webhook Subscriptions API — the only way to register this (Calendly has no webhook screen in its website).
  • Personal Access Token — authorises the one-time registration.
  • HMAC signing key — lets MarketingIQ verify each message; stored safely in Google Secret Manager (never in this page or in email).
  • MarketingIQ — Simple Digital's hosted attribution tool that receives and stores the bookings.

The live subscription

  • Event: invitee.created  ·  Scope: user  ·  State: active

Registering the webhook

Calendly webhooks are API-only — there is no button in the Calendly website, so registration is a single API call. Two things tripped it up along the way, worth remembering if it's ever rebuilt:

  • The token must have webhooks:write — a read-only token silently cannot create a webhook.
  • Subscribing to invitee.created also requires scheduled_events:read — Calendly rejects the request without it.

So the working token carried three permission groups: Webhooks (write), Scheduling (scheduled_events:read), and User management (read). Once registered, Calendly returned an active subscription and began delivering bookings.

Checking it works

You can confirm bookings and the webhook's health yourself with read-only Calendly API calls (for example in Postman). The step-by-step lives in postman_get_checks_instructions.txt. Three checks:

  • List recent bookings — confirm the booking is in Calendly.
  • Open the booking's invitee — see who booked and the tracking (UTM / click IDs) it carried.
  • Read the webhook subscription — state should be active and retry_started_at should be empty. If retries start, deliveries to MarketingIQ are failing.

What you can't see

You can't see the exact messages Calendly sent, or MarketingIQ's own record of them — those live on the agency's side. So the final "it arrived and was attributed" confirmation comes from Simple Digital.

Verified test

On 29 October 2026 a test Discovery Call booking appeared correctly in Calendly with its tracking, and the subscription stayed active with no delivery errors.

How it fits with our own tracking

MarketingIQ is a second, parallel path — it doesn't replace the Calendly tracking we already run.

Figure 2 — The same booking feeds both MarketingIQ (instant, via webhook) and our own sync (a scheduled batch into ActiveCampaign).

  • Our own calendly-source-sync reads the same bookings on a schedule and writes the source onto the ActiveCampaign contact, feeding our dashboard.
  • The difference is timing: MarketingIQ receives bookings in real time (useful for feeding the ad platforms), while our sync runs as a batch. Keeping both gives real-time delivery and an independent cross-check.
  • Both share one blind spot: bookings from direct links (email, LinkedIn, email signatures) arrive with no marketing source attached.
